## 11. 第七轮补充验证（`+4`）

### 11.1 Android ML Kit OCR（release 包）

| 项 | 内容 |
|---|---|
| 现象 | Debug 正常；Release 包中识别器初始化即失败：`Attempt to read from field 'xn1.a' on a null object reference in com.google.mlkit.vision.text.TextRecognition.getClient(...)` |
| 原因 | R8（`proguard-android-optimize.txt`）裁剪/优化了 ML Kit 通过反射注册的识别器与内部实现包，注册表字段为 null；与图片预处理无关 |
| 修复 | `client/android/app/proguard-rules.pro` 整体保留 `com.google.mlkit.**` 与 `com.google.android.gms.internal.mlkit_**`（含成员），替换原先只保留中文识别器的局部规则 |
| 独立图片 | 真机 release 包，相册选择 `test.png` → 1584 字，提示「识别文字已填入正文」；截图 `android-ocr-image.png` |
| PDF 内嵌图片 | 真机 release 包，导入扫描版 `ocr_scan.pdf`（无文本层，单页 1057×4803）→ 渲染后走同一 OCR 服务，1584 字，提示「扫描页已在本机用 ML Kit 中文离线模型识别」；截图 `android-ocr-pdf.png` |
| 稳定性 | 识别器在两次尝试（RGBA 位图 → 临时文件）间复用同一套 keep 规则；空白分块被忽略，不会中断整页识别 |

说明：定位阶段使用的临时 smoke 入口与测试图片已删除，正式包不含测试资源。

### 11.3 Windows 图标链路

| 检查 | 结果 |
|---|---|
| 窗口图标 | `FlutterWindow::OnCreate` 用 `LoadImage(IDI_APP_ICON, SM_CXICON/SM_CXSMICON)` 后 `WM_SETICON` 设置大小图标；`WM_GETICON` 读回非空，与新图标一致 |
| 任务栏 | 进程设置 `SetCurrentProcessExplicitAppUserModelID("RedPen.Desktop.1")`，安装程序的桌面/开始菜单快捷方式使用同一 AppUserModelID |
| 快捷方式 | `IconLocation = D:\红笔\red_pen.exe,0`，exe 内嵌同一图标 |
| 资源规格 | `app_icon.ico` 含 16/24/32/48/64/128/256 七档，无拉伸变形 |
| 图标未刷新 | 覆盖安装后桌面/任务栏仍显示旧图标：`ExtractIconEx` 只有 1 个图标组且为新图，`SHGetFileInfo` 与 `SHGetImageList(SHIL_JUMBO)` 解析快捷方式均为新图，判定为资源管理器图标缓存；安装程序增加 `ChangesAssociations=yes` 广播刷新，本机清理 `iconcache_*.db` 并重启资源管理器后恢复正常 |
| 任务栏复验 | 从安装目录启动并最小化，任务栏按钮为新图标；证据 `windows-taskbar-running.png` |
